# Project Documentation

The documentation is organized to preserve traceability from business analysis to implementation and testing.

## Structure

### 01-business-analysis
Business problem, stakeholders, scope, assumptions, constraints, business rules, and success metrics.

### 02-requirements
Functional requirements, non-functional requirements, use cases, user stories, and acceptance criteria.

### 03-process-models
AS-IS / TO-BE processes, BPMN, and workflow diagrams.

### 04-system-design
Architecture, ERD, sequence diagrams, data model, and technical decisions.

### 05-api
API contracts, endpoint specifications, request/response examples, and error handling.

### 06-testing
Test strategy, integration tests, UAT scenarios, and requirement traceability.

### 07-portfolio
Case study, screenshots, interview material, and final project presentation content.
